# Product-grade roadmap

Universal Manga Translator 的目标不是实验性地“能翻译漫画图片”，而是成为普通用户愿意长期使用的漫画翻译插件。主产品形态保持为 Chrome 插件：用户安装插件、配置 OCR API 和 OpenAI-compatible 翻译 API 后即可使用，不依赖命令行、桌面端或本地后端。

## North Star

用户在漫画章节页点击插件后，应该获得接近商业插件的体验：

- 启用明确：插件只在用户启用过的主域名运行。
- 上手简单：首次配置有清晰步骤，自检能直接说明问题。
- 翻译顺滑：第 1 页优先出结果，后续页面并发，进度准确。
- 成本可控：缓存可靠，失败不无限重试，OCR key 自动轮换。
- 排版自然：翻译气泡稳定、不闪、不漂移，遮罩尽量贴合原气泡。
- 翻译像人话：人名、术语、语气在同一章内保持一致。
- 工程可靠：每次发布前有自动测试、打包检查和人工验收清单。

## Product Principles

1. 插件优先。桌面端和后端只作为高级/实验入口，不能成为普通用户路径的一部分。
2. 默认少打扰。未启用网站不注入；已启用网站也只在漫画阅读页显示 UI。
3. 每个按钮都必须是真功能。Popup、悬浮按钮、进度条里的控件都要有测试覆盖。
4. OCR 成本优先保护。空结果不缓存，同图并发请求合并，额度/限流错误要立即停止无意义消耗。
5. 手动编辑优先级最高。用户改过或删掉的气泡不能被缓存、重翻、普通翻译覆盖。
6. 复杂能力放进高级配置。普通用户只看到必要设置，高级 OCR 字段映射放在折叠区。

## Phase 1: release foundation

目标：陌生用户可以根据 README 安装、配置、发现错误并完成第一次翻译。

范围：

- 首次配置：OCR API、翻译 API、模型、术语表、自检。
- 自检：OCR 真实请求、页面样本 OCR、翻译 `/models` 和 `chat/completions`、字段解析检查、常见错误翻译成人话。
- 发布文档：安装、API 配置样例、常见错误、权限说明。
- CI：`pnpm typecheck`、`pnpm test`、扩展 build/package。

验收：

- 新用户只看 README 和 quickstart 就能装上插件。
- OCR 402、401、429、字段路径错误都能在自检里显示明确原因。
- GitHub Release 主资产是 `extension-release.zip`。
- 每次发布前能自动验证 zip、checksum 和敏感文件排除。

## Phase 2: reader detection and queue behavior

目标：插件只在正确页面运行，并且翻译顺序符合用户直觉。

范围：

- 阅读页识别：章节 URL、连续大图、图片比例、阅读列布局综合判断。
- 非阅读页静默：目录页、首页、搜索页不显示漫画翻译 UI。
- 自动翻译顺序：第 1 页必须优先完成，后续页面并发。
- 单页翻译：图片左上角按钮只翻译该图片。
- 重翻当前页：只重翻当前可见页，不触发整章队列。
- 队列取消：取消后旧任务不能继续写回 UI 或缓存。

验收：

- 目录页启用网站后不自动翻译、不弹出阅读 UI。
- 自动翻译时第 1 张图先完成；第 2 张以后可并发。
- 悬浮按钮和 popup 的重翻不会把全章重新加入队列。

## Phase 3: OCR cost and provider reliability

目标：减少无效 OCR 消耗，同时兼容更多服务商和本地 OCR HTTP。

范围：

- OCR provider profile：URL、输入模式、字段映射、静态字段变化时自动隔离缓存。
- Key 池：额度不足、鉴权失败、限流时自动切换；状态显示不泄露 key。
- 请求合并：同图同配置的并发 OCR 只发一次。
- 空结果策略：空 OCR 不缓存；连续失败达到阈值暂停自动队列。
- OCR 调试视图：原始返回摘要、解析 region 数、过滤原因、耗时阶段。

验收：

- 换 OCR URL 或字段映射后不会复用旧 OCR/整章缓存。
- 同一图片并发翻译只产生一次 OCR 请求。
- 额度不足时能尝试下一个 key，并在全部失败后停止队列。

## Phase 4: translation quality

目标：翻译结果更像本地化漫画台词，而不是逐字机翻。

范围：

- Prompt 明确漫画场景：短句、自然口语、角色语气、避免解释腔。
- 章节上下文：前几页译文、人名候选、术语候选传给模型。
- 术语表强约束：用户指定译名必须优先。
- 重翻优化：重翻时传入上一版译文，要求改进通顺度和一致性。
- 一致性检查：同一英文名在一章内出现多个译名时记录警告。

验收：

- 同一章重复人名不会频繁变译。
- 重翻比首次翻译更自然，而不是随机换一种译法。
- 术语表变更后缓存自动失效。

## Phase 5: overlay rendering quality

目标：覆盖层尽可能像原生嵌字，且稳定不闪。

范围：

- 稳定排版：相同文本和相同框尺寸不重复改 DOM。
- 遮罩默认值：椭圆比例、缩放、透明度、圆角有成熟默认。
- 文本适配：短句放大，长句缩小，中文断行避免孤立标点。
- 气泡微调：单个气泡可隐藏、编辑、调整位置和大小。
- 框选优先：框选翻译区域永远不被普通翻译覆盖。
- 手动删除：文字删空后气泡消失并持久化。

验收：

- 滚动时气泡不相对图片抖动。
- 调整全局外观参数后已渲染气泡实时刷新。
- 手动编辑刷新页面后仍保留；删除的气泡不会复活。

## Phase 6: UI polish

目标：Popup、悬浮按钮、进度条接近成熟商业插件。

范围：

- Popup 主面板只保留高频动作：启用网站、翻译、重翻、框选、显示隐藏、自动翻译、设置。
- API 设置页分离：保存按钮明确，离开前不自动乱保存。
- 悬浮按钮：小、半透明、可拖动、右键展开二级动作。
- 图片左上角按钮：不同状态使用颜色表达，hover 后显示动作。
- 进度条：及时更新、可拖动、可折叠、可关闭。
- 错误提示：用户读得懂，不只显示 `fetch failed`。

验收：

- Popup 改任何设置不自动跳到顶部。
- 所有按钮都有对应测试，没有假按钮。
- 进度条在任务进入队列时立即显示状态变化。

## Phase 7: publishing and trust

目标：项目能作为 GitHub 开源项目公开给别人使用。

范围：

- README 完整：安装、配置、使用、本地 OCR、常见错误。
- 隐私说明：API key 存储位置、请求发送到哪里、不会上传什么。
- 权限说明：为什么需要 `<all_urls>`、`activeTab`、`storage`。
- Release checklist 自动化。
- Issue 模板：OCR 失败、翻译质量、网站兼容、UI 问题。

验收：

- 发布包不包含 `.env`、缓存、日志、个人 key。
- 报错用户能根据文档判断是额度、key、URL、字段映射还是模型问题。

## Backlog: advanced features

这些能力暂不进入主线，但保留方向：

- 擦除原文和背景重绘 / inpaint。
- 批量导出已翻译章节。
- 多浏览器适配。
- 移动端浏览器插件。
- 本地模型/OCR 一键部署。
- 漫画站点兼容性数据库。

## Current Priority

当前项目已经具备核心可用性。下一步优先级：

1. 继续收口 Phase 1 和 Phase 7：文档、发布包、CI、隐私和 issue 流程。
2. 复核 Phase 2：阅读页边界、队列冲突、重翻范围。
3. 打磨 Phase 6：popup、进度反馈、悬浮按钮细节。
4. 再集中投入 Phase 4 和 Phase 5：翻译质量与覆盖渲染细节。
